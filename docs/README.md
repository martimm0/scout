# Scout docs

Three documents, and they are meant to be kept current rather than accurate as of
some date in the past. If you change the thing, change the doc in the same commit.

| | |
| --- | --- |
| **[GAMEPLAN.md](GAMEPLAN.md)** | What the game is, why it exists, the rules it obeys, and where it is going. Start here. |
| **[ARCHITECTURE.md](ARCHITECTURE.md)** | How the code is put together. The load-bearing ideas, the frame loop, and how it is tested. |
| **[DATA.md](DATA.md)** | How the data is shaped. Species, parks, the save file, photographs, and how to add more. |

## What happened to the old ones

`SCOUT_MVP_GAME_PLAN.md` and `SCOUT_IMPLEMENTATION_PLAN.md` are gone. They are in
the git history if anybody wants them.

They were a spec written before the game existed and a running log of milestones
written while it was being built, and both had stopped describing the software.
The spec still promised one park and sixteen plants. The log had grown to nine
hundred lines and had duplicate sections in it, because it was appended to rather
than maintained.

A doc that has to be read with a date in mind is worse than no doc, because it
looks like it is telling you the truth. These three describe the game as it is,
and the intent is to keep them that way.
